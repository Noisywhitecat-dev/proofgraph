# /adr — ADR 작성

제목: $ARGUMENTS (비어 있으면 이번 대화에서 내린 결정 중 ADR이 필요한 것을 찾아 제안한다)

## 순서
1. `docs/adr/`의 파일 목록에서 가장 큰 번호를 찾고, 다음 번호를 네 자리로 정한다 (예: 0003 다음은 0004).
2. `docs/adr/0000-template.md`의 구조를 그대로 쓴다. 파일 이름은 `NNNN-영문-kebab-case.md`.
3. 내용을 채운다.
   - **맥락:** 왜 결정이 필요했는지, 제약(비용 상한, 입문자, 주 30시간 등)
   - **결정:** 한두 문장으로 분명하게
   - **검토한 대안:** 최소 2개. 장점, 단점, 선택하지 않은 이유
   - **결과:** 좋아지는 것, 감수하는 것, 다시 검토할 조건
   - **면접에서 설명한다면:** 2~3문장
   - **관련 질문:** `docs/QUESTIONS.md`에 해당 질문 ID가 있으면 연결한다
4. 사용자가 고르지 않은 결정이나 모르는 사실은 지어내지 않는다. 대안이나 이유가 불분명하면 AskUserQuestion으로 1~3개 묻는다.
5. 상태는 사용자가 결정을 확인했으면 "승인", 아니면 "제안"으로 둔다.
6. `docs/QUESTIONS.md`의 해당 질문 "반영" 칸에 ADR 번호를 적고, `docs/STATUS.md` 완료 목록에 한 줄로 남긴다.
