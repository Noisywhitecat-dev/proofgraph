# /til — 학습 로그 작성

주제: $ARGUMENTS (비어 있으면 이번 작업에서 배운 것 중 가장 중요한 것을 제안하고 사용자에게 확인한다)

## 순서
1. `docs/learning-log/README.md`의 템플릿과 `docs/STATUS.md`의 현재 단계를 확인한다.
2. 이번 작업이 `docs/ROADMAP.md`에서 **[직접]**으로 표시된 작업인지 확인한다.
3. 파일 이름을 정한다: `docs/learning-log/YYYY-MM-DD-주제.md` (오늘 날짜, 주제는 짧은 한국어 또는 영어 kebab-case). 같은 이름이 있으면 사용자에게 묻는다.
4. 작성 방식을 고른다.
   - **[직접] 작업이면:** 템플릿의 제목과 메타 정보(날짜, 단계, 관련 PR)만 채우고, 각 소제목 아래에 생각을 끌어내는 질문을 HTML 주석(`<!-- -->`)으로 2개씩 단다. **본문은 쓰지 않는다.** 사용자에게 "직접 채워 주세요, 다 쓰면 리뷰할게요"라고 안내한다.
   - **그 외:** 이번 대화와 커밋에서 실제로 한 일만 근거로 초안을 쓴다. 지어내지 않는다. 사용자에게 보여 주고 고칠 곳을 묻는다.
5. 새로 나온 용어가 `docs/glossary.md`에 없으면 추가를 제안한다.
6. 만든 파일 경로를 알려 준다. 커밋은 사용자가 원할 때 작업 브랜치에서 한다.

## 좋은 학습 로그의 기준
- "무엇을 했다"보다 "무엇을 이해했다"를 쓴다.
- 헷갈렸던 것과 어떻게 풀었는지가 가장 값지다.
- "면접 질문으로 바꾼다면"에는 실제로 답할 수 있는 질문을 1~2개 쓴다.
