# 0단계 기반: 개발 환경과 작업 방식 만들기

- 날짜: 2026-11-16
- 단계: 0단계 · 작업 0.8 [직접] (0.9 복습 내용 포함)
- 관련 커밋/PR: PR #1 (CI), PR #2 (main 보호 규칙), PR #3 (채팅 인계 규칙), PR #4 (Claude Code 작업 환경)

## 무엇을 배웠나
- **Docker 볼륨:** 컨테이너는 이미지로 언제든 다시 찍어 낼 수 있는 복사본이라, 지우면 안의 파일도 사라진다. 그래서 DB 데이터는 컨테이너 바깥의 볼륨에 둔다. 호텔 방(컨테이너)은 체크아웃하면 청소되지만, 개인 보관함(볼륨)의 짐은 남는 것과 같다. `just down`은 방만 비우고, `just nuke`(`down -v`)는 보관함까지 해지한다.
- **hook과 CLAUDE.md:** CLAUDE.md는 Claude가 읽고 따를지 판단하는 권고다. hook은 Claude Code 프로그램이 판단 없이 매번 실행한다. 그래서 질문할 때나 새 채팅을 열 때처럼 판단이 필요한 규칙은 CLAUDE.md에 두고, 포매팅처럼 코드의 동작을 바꾸지 않아 항상 실행해도 되는 일은 hook으로 만든다.
- **에이전트를 프로젝트에 맞추는 법:** 반복하는 일은 skill(`/til`, `/adr`, `/sync-status`)로, 역할이 정해진 일은 서브에이전트(`tutor`, `reviewer`)로, 지켜야 할 규칙은 설정 파일로 저장소에 남긴다. 그러면 대화마다 다시 설명하지 않아도 같은 방식으로 일한다.

## 왜 중요한가 (이 프로젝트에서)
- 볼륨을 모르고 1단계에 들어갔다면, 컨테이너를 정리하다가 쌓아 둔 증빙 데이터를 지울 수 있었다. 마이그레이션처럼 DB를 다루는 작업도 "데이터가 어디에 있는가"를 알아야 이해할 수 있다.
- hook이 없으면 포매팅은 Claude가 기억할 때만 실행된다. 이 프로젝트는 코딩뿐 아니라 AI와 함께 일하는 방식 자체도 연습하는 곳이라, "무엇을 AI의 판단에 맡기고 무엇을 자동으로 강제할지" 나누는 것이 기초가 된다.
- 예전 프로젝트에서는 Docker를 충분히 이해하지 못한 채 썼다. 이번에는 직접 설명할 수 있을 때까지 공부했다.

## 헷갈렸던 것과 해결
- 0단계 검수에서 "Docker 볼륨을 지우면 무엇이 사라지고, 왜 그런가?"라는 질문에 답하지 못했다. 0.5에서 설정은 동작했지만, 이해하지 못한 채 승인하고 넘어갔기 때문이다.
- 그래서 0.5를 처음부터 다시 공부했다. 이미지와 컨테이너, 포트, 볼륨, 초기화 스크립트, 헬스체크를 `compose.yaml`의 한 줄씩과 맞춰 봤다. 그다음 직접 테이블을 만들고 `just down` → `just up`을 한 뒤 데이터가 남아 있는 것을 확인했다. 실험 결과를 먼저 예상하고 확인하니 개념이 정확히 남았다.
- `just nuke` 뒤라면 결과가 달라진다. 볼륨까지 지워져 테이블과 데이터가 사라진다. 볼륨이 비었으니 다음 `just up`에서 초기화 스크립트가 다시 실행되어 확장 기능만 새로 켜진다.
- 이 일로, 지식이 부족하면 AI를 통한 개발에서 잘못된 결정도 승인하고 확인하지 못한 채 넘어갈 수 있다는 것을 알았다. 그래서 작업 규칙을 바꿨다. 이제는 단계마다 설명을 먼저 듣고 확인 질문에 답한 뒤에 진행한다(P0-D15). 로드맵의 모든 단계 완료 기준에도 "공부할 것마다 확인 질문에 답했다"를 넣었다(P0-R3).

## 면접 질문으로 바꾼다면
- **"이 프로젝트는 실제로 무엇을 위한 것인가요?"**
  규모가 크고 다양한 기술을 써야 하는, 회사에서 겪게 될 문제의 축소판을 직접 만들어 보는 학습 프로젝트입니다. 동시에 그 결과를 면접관에게 링크로 보여 주는 포트폴리오이기도 합니다.
- **"AI로 개발하면서 본인이 이해하지 못한 코드를 승인한 적은 없나요?"**
  있습니다. 로컬 인프라를 구성할 때 Docker 볼륨을 이해하지 못한 채 넘어갔다는 것을 검수 단계에서 발견했습니다. 다시 공부하고 실험으로 확인한 뒤, 작업 전에 설명을 듣고 확인 질문에 답해야 진행하도록 규칙을 바꿨습니다.
- **아직 자신 없는 부분:** 여러 언어를 쓰는 이유를 실제 경험으로 설명하는 것. 지금은 "넓게 쓰되 Python은 깊게"라는 계획(P0-D16)만 있고, 1단계에서 Java와 Python을 써 본 뒤 경험으로 답을 채운다.
