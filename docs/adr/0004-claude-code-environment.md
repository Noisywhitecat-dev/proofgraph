# ADR-0004: Claude Code 작업 환경 (`.claude/`)

- **날짜:** 2026-11-16
- **상태:** 승인
- **관련 단계:** 0단계 (0.7)
- **관련 질문:** P0-D10, P0-D11, P0-D12, P0-D13, P0-D14, P0-C9

## 맥락
이 프로젝트는 Claude Code와 함께 개발하는 방식 자체가 학습 대상이다 (ROADMAP 0.7).
매 세션 반복하는 일(포매팅, 학습 로그, ADR, 상태 갱신)과 지켜야 할 규칙(권한, 비밀값)을 대화마다 다시 말하지 않도록 저장소에 설정으로 남길 필요가 있었다.
제약: 사용자는 개발 입문자이고, 개발 환경은 Windows(PowerShell)와 CI(Linux) 두 곳이며, 추가 비용은 없어야 한다.

## 결정
`proofgraph/.claude/`에 다음을 둔다.

| 구성 | 결정 | 질문 |
|---|---|---|
| 권한 (`settings.json`) | **읽기 명령만** 허용 목록에 둔다. 커밋·push·삭제는 매번 확인한다. `.env` 읽기는 금지 | P0-D11 |
| 포매터 hook (`hooks/format.mjs`) | 파일 수정 직후(PostToolUse) 실행하는 스크립트를 **Node.js**로 쓴다. 포매터는 서비스를 만들 때 언어별로 연결한다 | P0-D10 |
| 경로별 규칙 (`rules/`) | `docs.md`는 지금 쓰고, java·python·typescript는 틀만 둔다 | — |
| 에이전트 | `tutor`: 설명 뒤 퀴즈 2~3개, 정답은 사용자가 답한 뒤 공개. `reviewer`: 읽기 전용 리뷰 | P0-D12 |
| skills | `/til`, `/adr`, `/sync-status`. STATUS 갱신은 기본 명령 `/status`와 겹쳐 `/sync-status`로 이름을 바꾼다 | P0-D13 |
| IDE | VS Code(무료)와 추천 확장 목록 `.vscode/extensions.json` | P0-D14 |
| 동작 확인 | `.claude/` 설정은 `proofgraph` 폴더에서 연 세션에서만 읽히므로, 확인과 이후 작업은 그 폴더에서 연 세션에서 한다 | P0-C9 |

`just check`에 `.claude/` 설정 파일 검사를 추가해 CI에서도 깨진 설정을 잡는다.

## 검토한 대안
| 대안 | 장점 | 단점 | 선택하지 않은 이유 |
|---|---|---|---|
| hook을 PowerShell로 작성 | Windows에 기본 설치 | CI(Linux)에서 별도 설치 필요, 문법이 낯섦 | 두 환경에서 같은 스크립트가 돌아야 함 |
| hook을 Python으로 작성 | 1단계에서 배울 언어 | 아직 Python 환경 미설치, 가상환경 관리 필요 | Node.js는 이미 설치되어 있음 |
| 권한: 읽기 + 커밋까지 허용 | 확인 질문이 줄어듦 | 의도하지 않은 커밋이 생길 수 있음 | 입문자는 커밋 단위를 직접 확인하며 배워야 함 |
| 권한: 최소(허용 목록 없음) | 가장 안전 | 읽기 명령마다 확인해야 해서 흐름이 끊김 | 읽기는 되돌릴 일이 없어 허용해도 안전 |
| tutor: 설명만 | 짧음 | 이해했는지 확인할 수 없음 | 학습 점검(L 유형)이 목적 |
| IDE: IntelliJ | Java 지원이 가장 좋음 | 언어별로 다른 IDE가 필요, 유료 기능 | 여러 언어를 한곳에서 보는 것이 우선. Java가 답답하면 1단계에서 무료 버전 검토 |

## 결과
- **좋아지는 것:** 반복 작업이 명령 하나(skill)로 줄고, 포매팅은 Claude가 잊어도 실행된다. 결정과 학습 기록의 형식이 일정해진다.
- **감수하는 것:** 커밋·push마다 확인을 눌러야 한다. 지금 hook은 연결된 포매터가 없어 기록(`format.log`)만 남긴다.
- **다시 검토할 조건:** hook이 느리거나 시끄러워 작업을 방해할 때 (ROADMAP 0단계 "진행 중" 질문), 서비스가 생겨 포매터를 연결할 때, 확인 질문이 너무 잦아 흐름을 끊을 때.

## 면접에서 설명한다면
"AI 코딩 도구를 쓰더라도 규칙을 대화에 맡기지 않고 저장소 설정으로 남겼습니다. 읽기만 자동 허용하고 커밋·push는 매번 확인하게 해 사람이 변경 단위를 통제하고, 포매팅처럼 매번 반드시 일어나야 하는 일은 hook으로 자동 실행되게 했습니다. 설정 파일 검사를 CI에 넣어 설정이 깨지는 것도 막았습니다."
