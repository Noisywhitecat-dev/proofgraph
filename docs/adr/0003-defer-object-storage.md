# ADR-0003: 객체 저장소(MinIO) 도입을 1.7로 미룸

- **날짜:** 2026-11-16
- **상태:** 승인
- **관련 단계:** 0단계 (0.5), 1단계 (1.7)
- **관련 질문:** P1-D6 (1.7 착수 시 결정)

## 맥락
계획에는 0.5에서 원본 문서 저장용으로 MinIO(S3 호환 객체 저장소)를 함께 띄우기로 되어 있었다.
그런데 2026-11-16 확인 결과, Docker Hub에서 `minio/minio` 이미지를 더 이상 받을 수 없었다 (`latest`, 2025년 릴리스 태그 모두 없음).
지금 0단계에는 객체 저장소를 쓰는 코드가 하나도 없다.

## 결정
0.5 로컬 인프라는 **PostgreSQL(+pgvector, pg_trgm)과 Redis만** 띄운다.
객체 저장소는 실제로 원본을 저장하는 1.7(수집기 v1)에서, 요구사항이 구체화된 뒤 고른다.

## 검토한 대안
| 대안 | 장점 | 단점 | 선택하지 않은 이유 |
|---|---|---|---|
| 지금 MinIO 대체재 도입 (SeaweedFS, Garage, RustFS 등) | 계획대로 진행 | 쓰지 않는 서비스를 미리 운영, 선택 근거가 없음 | "필요가 증명되기 전 도입 금지" 원칙 |
| MinIO 소스 빌드 | 원래 계획 유지 | 빌드·유지 부담, 배포 정책 변경의 위험 | 학습 가치 대비 비용이 큼 |
| **1.7로 미룸** | 실제 요구(용량, 접근 방식)를 보고 선택 | 1.7에서 결정 작업 추가 | 선택 |

## 결과
- 1.7 착수 시 `P1-D6`으로 묻는다: 원본을 S3 호환 저장소에 둘 것인가, 처음에는 Postgres나 로컬 파일로 충분한가?
- 그때의 후보: SeaweedFS, Garage, RustFS, LocalStack(S3), 로컬 파일 시스템. 5단계 클라우드에서는 실제 S3 같은 관리형 저장소를 쓴다.
- `PROJECT.md`의 저장소 항목 "S3/MinIO"는 "S3 호환 저장소(1.7에서 결정)"로 읽는다.

## 면접에서 설명한다면
"원래 MinIO를 쓰려고 했는데, 배포 정책이 바뀌어 공식 이미지를 받을 수 없게 됐습니다. 대체재를 바로 넣지 않고, 실제로 원본을 저장하는 시점까지 결정을 미뤘습니다. 쓰지 않는 인프라를 먼저 운영하지 않는다는 원칙을 지킨 사례입니다."
