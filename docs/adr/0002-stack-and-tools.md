# ADR-0002: 기술 스택과 도구, 작업 방식

- **날짜:** 2026-11-16
- **상태:** 승인
- **관련 단계:** 0단계
- **관련 질문:** P0-D1, P0-C2, P0-D5 ~ P0-D9

## 맥락
0단계를 시작하기 전에 목표 직무, 투입 시간, 저장소, 도구를 확정해야 이후 단계의 비중과 기간을 정할 수 있다.

## 결정
| 항목 | 결정 | 근거 |
|---|---|---|
| 목표 직무 | **AI 엔지니어** | 사용자 선택 (P0-D1). 3단계(RAG·평가·LLM 보안)를 핵심 단계로 격상하고, Python 비중을 키운다 |
| 투입 시간 | 주 30시간 이상 | 사용자 선택 (P0-C2). 로드맵 기간을 약 2/3로 줄인다 |
| 저장소 | GitHub `Noisywhitecat-dev/proofgraph`, 공개 | 커밋 기록 자체가 증빙 |
| 라이선스 | MIT | 가장 널리 쓰이는 관대한 라이선스 |
| 커밋 메시지 | 한국어, Conventional Commits 접두어 유지 (`feat(core-api): 로그인 추가`) | 사용자 선택 (P0-D6) |
| 커밋 이메일 | 이 저장소에만 GitHub noreply 주소 설정 | 공개 저장소에서 개인 이메일 노출 방지 |
| 태스크 러너 | **just** | 아래 대안 비교 |
| 월 비용 상한 | LLM API + 인프라 합계 **3만 원** | 사용자 선택 (P0-D8). 상한 안에서의 비용 최적화도 증빙 소재 |
| MCP 서버 언어 | Python | 사용자 선택 (P0-D9). ai-pipeline과 코드 공유 |

### 태스크 러너란
언어마다 실행 명령이 다르다 (`./gradlew test`, `uv run pytest`, `go test ./...`, `pnpm test`). 태스크 러너는 이 명령들을 `just test` 같은 **하나의 짧은 이름으로 묶어 주는 도구**다. 사람과 AI 모두 "이 저장소에서 테스트는 어떻게 돌리지?"를 외울 필요가 없어지고, CI도 같은 명령을 그대로 쓴다.

## 검토한 대안 (태스크 러너)
| 대안 | 장점 | 단점 | 선택하지 않은 이유 |
|---|---|---|---|
| **just** | 문법이 단순하고, Windows·macOS·Linux에서 똑같이 동작, 명령 목록을 `just --list`로 바로 확인 | 별도 설치 필요 | 선택 |
| make | 가장 표준적, 대부분의 Linux에 기본 설치 | Windows에서 설치와 동작이 불편, 탭 문법 등 함정이 많음 | 주 개발 환경이 Windows |
| Task (go-task) | YAML, 변경 감지와 의존성 기능 | 단순 명령 모음에는 과함, YAML이 길어짐 | 지금 필요한 기능이 아님 |
| npm scripts | 추가 설치 없음 (Node 사용 시) | 다언어 저장소에서 Node에 종속, 긴 명령 작성이 불편 | 언어 중립적이지 않음 |

## 결과
- just는 0.4 작업에서 설치한다 (Windows: `winget install Casey.Just`). 설치 전에 사용자에게 확인한다.
- AI 엔지니어 목표에 맞춰 로드맵을 조정한다: 3단계를 가장 깊게, 1.9(LLM 추출)와 2.5(근거 기반 생성)에도 평가를 붙인다.
- 다시 검토할 조건: 목표 직무가 바뀌거나, 비용 상한을 두 달 연속 초과할 때.

## 면접에서 설명한다면
"여러 언어가 섞인 저장소라 실행 명령이 제각각이어서, just로 명령을 하나의 진입점에 모았습니다. 사람과 CI, AI 에이전트가 모두 같은 명령을 쓰기 때문에 '로컬에서는 되는데 CI에서는 안 된다'는 문제를 줄일 수 있었습니다."
